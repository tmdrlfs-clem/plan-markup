# Story 2.1: Spike — `.btx` parse and render

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As the founder,
I want to know that my Revu tool sets can be read and drawn faithfully,
so that the Tool Chest import (FR42) is feasible at ≥95 % fidelity.

## Acceptance Criteria

1. **Given** the founder's three `.btx` files in `fixtures/private/btx/` (`sprinkler-tools.btx` 66 items, `fire-alarm-tools.btx` 56, `my-tools.btx` 16 = 138 items, git-ignored), **when** the prototype parser in `src/core/btx/` runs (in a Web Worker in the browser, directly in Node for the harness and tests), **then** it decodes the XML, the hex + zlib values and the raw PDF annotation dictionaries and resources into a typed `BtxToolSet` for all 138 items.
2. Untrusted-input limits (NFR31): input file ≤ 32 MB; every hex value ≤ 16 MB of hex; each inflated value ≤ 8 MB and the running total per file ≤ 128 MB (checked **while** inflating, not after); any `<!DOCTYPE` / `<!ENTITY` / processing instruction other than the XML declaration is rejected; XML depth ≤ 16; PDF object nesting depth ≤ 64; `BBObjPtr_*` reference graph is resolved without cycles blowing the stack. Each limit has a unit test that trips it with a small crafted input and gets a typed `BtxError` (code + message, no file content in the message).
3. Each item renders to a canvas (pdf.js 6.4.299, `isEvalSupported: false`) through one pipeline: build a one-page in-memory PDF that holds the item's annotation(s) and resolved resources, then let pdf.js draw it with annotations. Items whose annotation has no `/AP` (Circle, Square, Line, PolyLine, Ink, FreeText, Revu image-squares with `/Image`) get an appearance stream generated by our code from the dictionary (`/Rect`, `/C`, `/IC`, `/BS` incl. dashes, `/RD`, `/Vertices`, `/L`, `/InkList`, `/Image`), not by pdf.js's fallback.
4. A Node harness (`npm run spike:btx`) compares each rendered item with its reference image using a pixel diff (A9) and writes `docs/spikes/2-1-btx-report.md`: per-item row (set, index, name/subject, type, has AP, pass/fail, diff %, reason) and the overall pass rate against the ≥95 % target (NFR10). Reference images come from Revu (see Dev Notes → Reference capture). Until the references exist, the harness still runs, renders every item to `fixtures/private/btx/out/` plus a contact sheet PNG per set, and the report says "references missing" instead of a pass rate.
5. A synthetic `.btx` (no client content: hand-made shapes, made-up names) is committed to `fixtures/btx/synthetic.btx` with a generator script, and unit tests parse it end to end (stamp with AP + XObject + font resource, circle without AP, group with a `Child`, polyline, line).
6. The report ends with a go / change decision and the recommended import strategy for FR42 (what becomes a vector tool, what falls back to an image stamp — PRD risk table), plus the list of failing items with reasons.
7. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` pass. The harness is not part of CI (it needs private fixtures); the synthetic-file unit tests are.

## Tasks / Subtasks

- [x] **Task 1: XML reader** (AC: 1, 2)
  - [x] `src/core/btx/xml.ts`: a small, strict reader for the `.btx` shape only (no general XML library; `DOMParser` does not exist in Web Workers). Strip a UTF-8 BOM, accept `<?xml ...?>`, reject DOCTYPE/ENTITY/other PIs/CDATA, decode the five predefined entities and numeric character references only. Produce elements `{ name, attrs, children, text }` with the depth limit.
  - [x] Expected structure: `BluebeamRevuToolSet[Version]` → `Title` (hex) + `ToolChestItem[Version]*`. Item children: `Resources*` (`ID` hex, `Data` hex), `Name` (plain), `Type` (plain, e.g. `Bluebeam.PDF.Annotations.AnnotationBRXStamp`), `Raw` (hex), `X`, `Y`, `Index` (plain numbers, only on group members), `Child*` (same `Type/Raw/X/Y/Index` shape), `Mode` (plain, e.g. `drawing`). Unknown elements are kept as warnings, not errors.
- [x] **Task 2: Hex + zlib** (AC: 1, 2)
  - [x] `src/core/btx/inflate.ts`: hex → bytes (reject odd length / non-hex), then zlib inflate with `DecompressionStream("deflate")` (zlib-wrapped; available in Chrome, Node ≥ 18 and workers — no new dependency), reading chunks and aborting as soon as the per-value or per-file budget is exceeded. Text values decode as UTF-8 if valid, else Latin-1. Async API.
- [x] **Task 3: PDF object parser** (AC: 1, 2)
  - [x] `src/core/btx/pdf-object.ts`: tokenizer + parser for the PDF object syntax used in `Raw` and `Data`: dictionaries, arrays, names (with `#xx`), literal strings (escapes, balanced parens), hex strings (`<feff…>` → UTF-16BE), numbers, booleans, null, and `stream … endstream` after a dictionary (bytes taken by `/Length`, falling back to the `endstream` marker; there is trailing padding before `endstream`). References are names of the form `/BBObjPtr_<16 uppercase letters>`; represent them as `{ ref: "<ID>" }`. Depth limit.
  - [x] `src/core/btx/parse.ts`: `parseBtx(bytes: Uint8Array): Promise<BtxToolSet>` → `{ title, items: BtxItem[], warnings }`, `BtxItem = { name, type, mode, annotations: BtxAnnotation[] /* root first, then children with x/y/index */, resources: Map<id, PdfObject> }`. Validate the result with Zod (architecture: Zod at every parser boundary). Detect missing references and report them per item instead of throwing.
- [x] **Task 4: Worker entry** (AC: 1)
  - [x] `src/workers/btx.worker.ts`: `{ type: "parse", reqId, bytes }` → `{ type: "result", reqId, toolSet }` (structured-clone friendly: plain objects/arrays/`Uint8Array`, no `Map`) or `{ type: "error", reqId, error: serializeWorkerError(e) }` (`src/core/worker/error.ts`). Transfer the input buffer. A unit test calls the message handler function directly (no real Worker in Vitest).
- [x] **Task 5: Item → one-page PDF** (AC: 3)
  - [x] `src/core/btx/to-pdf.ts`: build a PDF with `@cantoo/pdf-lib` 2.11.1 (`PDFDocument.create`, `context.register`/`context.obj`, raw stream objects): convert every resource into an indirect object (map `BBObjPtr_X` → `PDFRef`), write the annotation dictionaries into the page `/Annots` with their `/AP /N` pointing at the converted XObject. Place the root at its `/Rect`; children at root origin + `(X, Y)` (verify the sign convention against a reference and record it in the report). Page box = union of rects + 4 pt margin. Drop Revu `Temp*`/`BB*` private keys only where they break viewers; keep everything else.
  - [x] `src/core/btx/appearance.ts`: generate `/AP /N` form XObjects for annotations without one: Square/Circle (stroke `/C`, fill `/IC`, width `/BS /W`, dash `/BS /D`, inset `/RD`, ellipse with 4 Béziers), Line (`/L`, line endings: none and the ones present in the fixtures), PolyLine (`/Vertices`), Ink (`/InkList`), Square with `/Image` (draw the referenced image XObject into the rect), FreeText (`/DA` font + `/Contents`, default Helvetica). Line join/cap round for Ink. Width 0 = no stroke.
- [x] **Task 6: Render + harness** (AC: 3, 4, 6)
  - [x] `scripts/spike-btx/render.mjs`: load the PDF with `pdfjs-dist/legacy/build/pdf.mjs` in Node, `isEvalSupported: false`, render with `@napi-rs/canvas` (already in `node_modules`; add it as an explicit devDependency at the installed version, exact pin) at 4 px per pt (≈ 288 dpi) with `annotationMode: AnnotationMode.ENABLE`, white background. Same code path the browser will use (pdf.js on a canvas); only the canvas factory differs.
  - [x] `scripts/spike-btx/run.mjs` (`npm run spike:btx`): parse each private `.btx`, render all items to `fixtures/private/btx/out/<set>/<nnn>-<slug>.png` and a contact sheet `<set>-sheet.png` (grid with index labels), then diff against references if present (Task 7) and write the report. Exit 0 even when items fail (it is a measurement), non-zero only on crashes.
  - [x] Pixel diff: add `pixelmatch` (latest stable, exact pin, devDependency) and `pngjs` if needed. Before diffing, trim both images to their non-white bounding box and scale the candidate to the reference size. Pass = diff ≤ **2 %** of the reference's non-white pixels with pixelmatch `threshold: 0.1` and anti-aliasing ignored. Keep the threshold in one constant and print the diff % per item so the founder can judge borderline cases; record the chosen value in the report.
- [x] **Task 7: Reference intake** (AC: 4)

Revu writes an appearance stream for every placed markup, so this is Revu's own drawing even for items that had no `/AP` in the `.btx`.
  - [x] If a `fixtures/private/btx/reference/<set>/<nnn>.png` exists (direct Revu image export), it wins over the PDF-derived one.
  - [x] Report a count mismatch (placed annotations vs items) clearly and match by `/Subj` + type as a fallback.

  - [x] Unit tests (node env, co-located): xml reader (structure, BOM, entities, DOCTYPE rejected, depth), inflate (budgets, bad hex), pdf-object (each token kind, stream with padding, `#xx` names, UTF-16 strings, depth), parse of `synthetic.btx` (5 items, types, refs resolved, group children), to-pdf (output loads in pdf-lib, `/Annots` count, refs resolved), appearance (operators for circle/line/ink, width 0 → no stroke). ## Dev Notes

### Context

First of the four A13 risk spikes. Goal: evidence that the founder's 138 Revu tools can be imported at ≥ 95 % visual fidelity before Epic 7/FR42 builds on it. This is a **spike**: production-quality parser in `src/core/btx/` (it will be kept and hardened for FR42), throwaway-quality harness in `scripts/spike-btx/`. No UI.

### What the `.btx` format looks like (verified on the founder's files, 2026-10-20)

- UTF-8 XML with BOM. Root `BluebeamRevuToolSet Version="1"`. `Title` and every `ID`/`Data`/`Raw` value is hex of a zlib stream (`789c…`). `Name`, `Type`, `Mode`, `X`, `Y`, `Index` are plain text.
- `Raw` = one PDF annotation dictionary, e.g. `<</Subtype/Stamp/Rect[…]/AP<</N/BBObjPtr_TKBMAYOQQAHPBTNE>>/C[1 0 0]/Subj<feff…>/Rotation 0/…>>`.
- `Resources` = (`ID` = 16 uppercase letters, `Data` = a full PDF object body, often `<<…/Length n…>>stream\r\n…` + newline padding + `endstream`). References between objects are names `/BBObjPtr_<ID>`. Resource kinds seen: form XObjects (nested), fonts (TrueType, Type1, Type0 + CIDFontType2, descriptors, widths arrays like `[278 …]`), images (FlateDecode, DCTDecode, CCITTFaxDecode). Largest single inflated resource ≈ 547 KB; files are 0.7–6.7 MB.
- Annotation types per set (`Type` → PDF `/Subtype`):
  - sprinkler-tools (66): BRXStamp→Stamp 46, Circle 16, Line 8, Polyline 3, MeasureCount→`RL` 3, BBImage→Square 2, FreeText 2, Ink 1.
  - fire-alarm-tools (56): BRXStamp→Stamp 43, BBImage→Square 13.
  - my-tools (16): Stamp 8, Circle 7, Line 4, Polyline 1, Ink 3.
- `/AP` present: all Stamps and `RL`. **Absent** on all Circle, Square (BBImage, uses `/Image /BBObjPtr_…`), Line, PolyLine, Ink, FreeText → about 54 items need generated appearances (Task 5). This is the main fidelity risk.
- Revu-private keys appear (`TempBBox`, `TempRT`, `TempIRT`, `TempGroupNestingName`, `TempNameID`, `TmpScaleX/Y`, `TmpBorderIndicator`, `IT/StampSnapshot`, `/RD`). Keep them in the typed model; they are useful for FR42 (group nesting, scale).
- `RL` is Revu's count-measurement subtype; treat as an annotation with AP (render only).
- Scripts to inspect the files exist only as throwaway Python in the session scratchpad; do not commit decoded client content anywhere.

### Review Follow-ups (AI)

High-effort code review of a6b357e, 10 findings, all fixed (each with a unit test):

- [x] 1. `inflate.ts`: the input is written to `DecompressionStream` in 8 KB slices (`INFLATE_SLICE_BYTES`) interleaved with reads; on a budget overrun the reader is cancelled and the writer aborted, so a bomb is never expanded far past the budget (test with an expanding fake inflater: at most 4 slices fed of 1 MB).
- [x] 2. `to-pdf.ts`: the `Converter` converts `BBObjPtr` targets from a work list instead of recursing through `ref() → value() → dict() → ref()` (20 000-long chain test; the old code throws `RangeError`).
- [x] 3. Count limits in `limits.ts` with new codes: PDF values per file 1 000 000 (`pdf-too-many-nodes`), items 1 000 (`too-many-items`), Child per item/file 64/1 000 (`too-many-children`), Resources per item/file 4 096/32 768 (`too-many-resources`); ≥ 10x the real maxima (≈ 55 000 values, 66 items, 2/15 children, 394/1 773 resources). `readLiteralString`/`readHexString` write into a growable `Uint8Array` instead of `number[]`. Limits documented in the report's NFR31 table.
- [x] 4. `btx.worker.ts`: error replies carry `code` when the error is a `BtxError`; `serializeWorkerError` unchanged.
- [x] 5. `btx.worker.ts`: every message gets a reply; malformed requests get an error reply with the `reqId` echoed when it is a finite number, else `reqId: null`. `bytes` may be a `Uint8Array` or an `ArrayBuffer`.
- [x] 6. `image.mjs` `compare()`: fails with "size differs" when the ink boxes differ by more than 5 % or 2 px (whichever is larger) in width or height, then scales the candidate uniformly (one factor, centred).
- [x] 7. `parse.ts`: per-item failures (bad hex/zlib/PDF token, non-finite number, missing Raw, failed per-item Zod validation) skip that item with a warning naming the item (and child/resource) index and the reason; limits, XML structure, root and Title still fail the file. Non-finite numbers are rejected by the PDF tokenizer.
- [x] 8. `parse.ts`: a missing `<Type>` on an item or Child is an item-level error ("Item 3 child 1: missing <Type>").
- [x] 9. `btx.worker.ts`: `btxReplyTransfer(reply)` lists every byte buffer of the tool set (deduplicated; views that do not own their whole buffer are copied first) and the worker posts the result with it.
- [x] 10. `run.mjs`: the self-reference layout moved to `reference.mjs` `layoutPlacements()`, which leaves out items without bounds and returns the reason; the harness adds it to the item's row.
